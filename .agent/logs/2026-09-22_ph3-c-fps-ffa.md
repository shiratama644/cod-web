## 3. 気づいたこと・知見 (Insights & Lessons Learned)

- **gamemodesはsdkのみimport**: biome.jsonでgamemodes/*→gamemode-sdkのみ禁止が既に設定済み。ffaは`import { defineGameMode } from '@cod/gamemode-sdk'`のみでOK、protocol/engine-core/profile-*を直接importしない。pvpエイリアスは`../ffa/index.ts`の相対importだが、BiomeのnoRestrictedImportsは`@cod/*`パターンのみなので相対importは許可される。理想は`@cod/gamemode-sdk`経由のre-exportだが、同一gamemodes内の相対importは許容。
- **spawnPointsはctx経由で疎結合**: world specはmap名のみ、spawnPointsはFpsCtx.getSpawnPoints()で取得、randomIntで選択。profile-fpsのstatic-arenaを再利用、three-mesh-bvh衝突はprofile側維持、gamemodeはルールのみ。
- **afterはtick基準**: 60Hzで3秒=180 ticks、5秒=300 ticks。setTimeout禁止を`grep -R setTimeout gamemodes` 0件で保証。GameModeTimerのafter/everyがtick基準なので、ffaのafterもtick基準で決定論。
- **スコアと勝利条件**: kill→scoreはonPlayerDeathでkiller.idのscore+1、10キルでended。playing中にplayers<2でended、ended後にafter 60*5でwaitingへリセット+score reset。最小FFAとして十分。
- **chat 200文字制限**: server.mdハード上限chat 200文字をonNetworkMessageで`slice(0,200)`。ModeMessage 0x20のdata 2048B制限は将来。
- **lint重複tick**: 初期実装で`const tick=0` + `tick,` + `tick:0`の重複で`noDuplicateObjectKeys`エラー。`tick:0`を1つに統一で解消。biome check --writeで74ファイル自動修正されたが、重複はunsafe fixなので手動修正必要。
- **coverage include-all維持**: gamemodes追加で1414 statements 1321 covered 93.42%、閾値85維持。ffaは11 testsでカバー。
