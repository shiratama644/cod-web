# skills の定義を是正（Agent のスキルであり、仕様書の要約メモではない）

> Date: 2026-09-03(JST) / Commit: `98cca3e`（SHA追記は後続）/ Branch: arena/01a062ac-cod-web

## 1. 指示内容 (Task Summary)

- ユーザー指摘: 「skills は agent のスキルです。仕様メモでもなんでもありません。**スキル**です。」
- 前回 docs/arch 分離の際、`.agent/skills/` を「正本 docs/arch の要約・メモ」「実コード由来の事実だけ」と格下げする書き方をしたが、これは誤り。スキルは**エージェント自身の能力・ノウハウ・テクニック・手順・パターン**そのもの。

## 2. 是正した役割分担

| 場所 | 正しい役割 |
|---|---|
| `docs/arch/` | 設計**仕様書**の正本（技術選定・プロトコル・設計ルール。「こういう設計」） |
| `docs/planning/` | 計画書（何を・どの順で・完了条件） |
| **`.agent/skills/`** | **Agent のスキル**: 「こうやるとうまく作れる/ハマらない」という実践的なノウハウ・テクニック・手順・パターン・コードベース知識。仕様書の要約ではない |
| `.agent/hooks/` | トリガー起動の定型ワークフロー |

## 3. 更新ファイル

- `AGENTS.md` §8 冒頭・§8.1（skills の定義表）・§8.4（AGENT.md/skills/docs/arch の三者役割分担を明記）・§6.7 の skills 言及
- `.agent/skills/index.md`: 「Agent のスキル集」として、各スキルを「できるようになること（Agent の能力）」視点で記述。設計の正本は docs/arch と明記しつつ、スキルは要約ではなく実践ノウハウとして位置づけ
- `.agent/skills/tech-stack.md`: 冒頭を「技術構成を使いこなすスキル（どこでどう使うか・ハマりどころ）」にリフレーム。正本は docs/arch/tech-stack.md を参照

## 4. 気づき・知見

- skills と仕様書の違い: 「**こういう設計になっている**」が仕様書（docs/arch）、「**こうやるとうまく作れる・ハマらない**」がスキル（skills）、「**こう作業せよ**」が規約（AGENTS.md）。スキルはライブラリの使い方・回避策・コードパターンといった実践能力を含んでよく、コードが無い段階の設計知見も「スキル」として持ってよい。
- 設計の事実そのものの正本は docs/arch に一元化し、スキルはそれを参照しつつ実践テクニックを書く、という分担で重複と乖離を防ぐ。

## 5. 次にすべきこと

- Phase 0 実装を進める中で、実際にライブラリを動かして得たコツ・ハマりどころ・手順を `.agent/skills/` にスキルとして蓄積する（設計仕様の変更は docs/arch を正本に更新）。
