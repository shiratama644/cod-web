# Diff Review Report — 差分レビューレポートの作成

> TEMPLATE_REPO(PalmIDE由来)を cod-web 用に調整。3ファイル以上または判断を伴う変更（破壊的変更・大規模リファクタ・仕様改訂）で作成する。

## 形式

```markdown
# 差分レビュー報告書 — X → Y

> 作成日: YYYY-MM-DD / 対象: （旧→新の範囲）
> 目的: 何をレビューしてほしいか1行で

## 1. 統合の方針        — 数値化できない判断の宣言（箇条書き5点程度）
## 2. 全体サマリ        — 総行数、ファイル数の表
## 3. 行数変化（ファイル別）— 旧/新/差分/主な変化理由の4列表
## 4. 意図的な変更点     — (1) 本文改変 (2) 削除 (3) 圧縮・簡素化 (4) リンク修正
## 5. 機械検証結果       — grep/リンク/検証コマンドの結果を期待値つきで
## 6. レビューポイント    — 人間判断を仰ぐ事項を表で。理由と懸念を必ずセット
## 7. まとめ
```

## 作成手順

1. `wc -l` で旧新の全ファイル行数を取る（数値は実測のみ、推定で書かない）
2. `git diff --stat` で変更範囲を確定
3. 差分を「追加 / 削除 / 圧縮 / リンク修正」の4分類に仕分け
4. 人間判断を仰ぐ事項は表に集約し、理由と懸念をセットで書く
5. 「変えたつもり」ではなく「実際に変えた場所」を `git diff` で確認してから書く

## 保存場所

- `docs/audit/diff-{context}.md` に保存
- **時点記録のため、後から書き換えない**。修正は新レポートで（`rules/01` の追加のみ原則）。

## cod-web での使いどころ

- プロトコル/ワイヤレイアウト変更（Input 16B・Channel framing に触れる変更）
- フロントエンド入れ替え級の大規模変更（例: 2026-10-03 Vite→Next 2a93a99）
- R7 INTEGRATION_SPEC の改訂時
