# docs/planning — 個別タスク詳細計画書の置き場

> このディレクトリは、**ROADMAP.md に登録された各タスクの「詳細計画書」**を置く場所です。
> 進捗管理（状態・進捗・証拠）は **`docs/ROADMAP.md` が正本**。本ディレクトリは
> 「各タスクの **目的・範囲・禁止事項・完了条件（DoD）・停止条件・設計詳細・リスク・実績**」という
> **「なぜ」と「詳細」**を担います。

## 役割分担（3 層）

| ファイル | 役割 | 何を持つか |
| :-- | :-- | :-- |
| `docs/ROADMAP.md` | **進捗管理の正本** | タスク ID / フェーズ / 状態 / 進捗 / 完了条件 / 証拠 |
| `docs/planning/_TEMPLATE.md` | **書式テンプレート** | 計画書の必須構造（§1〜§9）+ 任意（§10〜§12） |
| `docs/planning/*_PLAN.md` | **個別タスク詳細計画** | 目的（Why）/ 変更範囲 / 禁止事項 / DoD / 停止条件 / 設計詳細 / リスク / 実績 |

## 命名規則

- `docs/planning/<タスクID>_PLAN.md`（例: `P1-A_PLAN.md`、`P2-B_PLAN.md`）
- タスク ID は `docs/ROADMAP.md` の採番と一致させる。**ID は再利用しない**。
- 1 つの計画書 = 1 つのタスク（ROADMAP の 1 行）。複数タスクを 1 ファイルにまとめない。

## 使い方（新規計画書を作る流れ）

1. `docs/ROADMAP.md` にタスクの行を追加（ID 採番・状態・完了条件・証拠の枠を記入）
2. `docs/planning/_TEMPLATE.md` を複製して `<ID>_PLAN.md` を作成
3. §1〜§9（必須）を埋める。§10〜§12（設計詳細・Gotchas・実績）は必要に応じて
4. 実装完了時: **この計画書の §12（実績）と `docs/ROADMAP.md` の状態・進捗・証拠を更新**
