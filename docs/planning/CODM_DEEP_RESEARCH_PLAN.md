# CoD Mobile ディープリサーチ計画 — システム全面入れ替え（Rフェーズ）

> Date: 2026-09-24(JST) / Status: **確定（決定事項反映済み）— R0 開始可**
> 目的: arsenal.io（Web FPS）のシステムを全面入れ替え。*Call of Duty: Mobile*（以下 CoD Mobile）の**仕組みと機能**を完全にディープリサーチし、それを Web 上でできる限り再現する。
> 位置づけ: 本計画は `ARSENAL_IO_DESIGN_PLAN.md`（旧デザイン案）を**保留・代替**する。旧案の IA（rank/match/br/zombie + VALORANT 風）は、本研究の統合（R7）で最終 IA が出るまで凍結する。
> 本フェーズは**リサーチのみ**。コード変更ゼロ。実装は統合Spec承認後の別フェーズ（Sフェーズ）。

## 0. 前提

1. **IP 境界**: 再現対象は「仕組み・ルール・数値・フロー・UX 構造（アイデア）」のみ。アート / 3D / 音源 / マップの正確な幾何 / 公式キャラ・武器・ブループリントの固有名詞は**再現しない**（オリジナルまたはジャンル共通語で置換。"TDM" / "Domination" 等のジャンル通用モード名は可）。
2. **基準バージョンの固定（決定: 初出期）**: 基準は **2019-11 リリース ~ 2020-08 Zombies 導入前の初出期**（MP+BR コア）。Zombies / DMZ: Recon / Undead Siege は初出期に存在しないため、本基準の再現対象から除外する（R4 は別ミニ基準で後フェーズ）。
   - **Ranked の導入時期は R0 で必ず検証**: 初出期窓内に Ranked（MP）が含まれていなければ、参照窓を Zombies 導入前の Ranked 導入パッチまで延伸し、その旨を `00_scope.md` に明記する（DMZ / Undead Siege は引き続き対象外）。
   - 数値もバランスパッチで変わるため、R0 で**参照パッチを 1 つに確定**し、各ドキュメントに明記する。
3. **検証ポリシー**: 重要数値は 2 以上の情報源でクロス検証。各数値に信頼度ラベル `[検証済み]` / `[単一情報源]` / `[概算・設計値]` を付す。すべての結論にソース URL を記載。
4. **現状確認（計画作成時のスナップショット）**:
   - 現在の CoD Mobile は **Multiplayer / Battle Royale / Zombies / DMZ: Recon** の 4 系統（+期間限定イベントモード: Warfare, Ground War Skirmish, Alcatraz, Tank Battle, Sniper Royale 等）
   - Ranked は **MP と BR で別々のランク系列**（各 32 ランク、"Rookie〜Legendary"）。MP Ranked は 5 モード（Frontline / TDM / Domination / Hardpoint / S&D、期間限定で Kill Confirmed / Payout S&D / Safeguard / Patrol 等）。BR Ranked は**受動的に XP 獲得**（マッチ自体が対象かどうかで表示が変わる）
   - Ranked は **2 か月（バトルパス 2 シーズン）の "Series"** 単位。配置試合 3 試合でランク確定
   - Zombies は 2 形態: 従来型（ラウンド/ウェーブ制）と **Undead Siege**（2021/8 追加、基地防衛 PvE、Casual/Hard）
   - ランク報酬: カモフラージュ / 武器ブループリント / キャラ・キャラスキン / アバター / フレーム / 車スキンの他、ステッカー・チャーム・コールカード

## 1. 研究フェーズ構成（R0 → R7）

```
R0 (scope/ソース基盤)
 ├─ R1 MPコア ──┐
 ├─ R2 Ranked ──┤  並列可（R1 が基準）
 ├─ R3 BR ──────┤
 ├─ R4 Zombies ─┼──→ R7 統合Spec（最終成果物）
 ├─ R5 経済 ────┤
 └─ R6 UI/ソーシャル ┘
```

各ドキュメントの標準構成（1 システム 1 セクション）:
**① 仕組み**（ルール・数値・フロー・条件分岐を完全記述）→ **② ソース**（URL 一覧 + 信頼度）→ **③ Web 再現アプローチ**（sim/protocol/netcode/UI への影響）→ **④ 優先度**（P0 コア / P1 重要 / P2 後回し / P3 保留）

### R0: Scope とソース基盤（ゲート）
- 対象: **初出期の正確な参照パッチを 1 つに確定**（リリース日 ~ Zombies 導入前の範囲内で、第7節の決定に整合する最新版を特定）
- **Ranked の導入時期を検証**し、必要なら参照窓を延伸（前提2 参照）
- 初出期の**モード一覧・マップ一覧・シーズン構造（シーズン1~Zombies導入前）**を確定し、各 R フェーズの範囲を確定
- 対象機能マトリックスの**骨格**作成（第2節の全システムを 1 行ずつ並べ、各 R フェーズの担当を割り当て）
- 成果物: `docs/research/codm/00_scope.md`（機能マトリックス: 機能 × 担当フェーズ × 優先度 × 状態 + 参照パッチ明記）
- 完了基準: 全システムに担当フェーズと初期優先度が付いていること、参照パッチが 1 つに確定していること

### R1: MP コア（最重要・他フェーズの基準）
1. **モード定義**（各モード: 勝利条件 / オブジェクト / 採点 / リスポーン / 試合時間 / 必要マップ / HUD・スコアボード要素 / 終了画面）
   - 通常: TDM, FFA, Domination, Hardpoint, Search & Destroy, Kill Confirmed, Frontline, Control, Patrol, Safeguard（+基準版時点の期間限定モード一覧）
   - ** Ranked 专用パラメータ**（例: TDM 50K / Dom 75-75 割与 / S&D 5R — バージョン毎に検証）
2. **マップ**: 一覧 + 各マップの構成（レーン / スパーン / オブジェクト配置 / モード適合性）
3. **ロードアウト**: 数（スロット数）/ 構成ルール（武器・装備・パーкъの組みわせ）/ デフォルト / 編集フロー
4. **武器**: 全一覧（クラス分類）+ 武器毎のデータ表（ダメージ: 頭/体/四肢倍率、距離減衰、火器毎のヘッドショット倍率 / 射速 / マガジン / ADS 時間 / リコイル特性 / アタッチメントスロットと適合 / レベル別アンロック順）
5. **パーкъと装備**: 全一覧 + 正確な効果（数値付き）
6. **移動モデル**: スプリント / スライド / スライドジャンプ / クロールのタイミングと速度値（公開分）
7. **マッチフロー**: ロビー → カウントダウン → 開始 → インターミッション → 終了、キルフィード、スコアボード表示
- 成果物: `01_mp_modes.md` / `02_weapons.md`（データ表中心）/ `03_loadout_perks_movement.md` / `04_maps_matchflow.md`

### R2: Ranked
- ランク構造: MP（32 ランク / Rookie〜Legendary / 各 Div の条件）と BR（受動 XP 制）の**両方**
- MMR の振る舞い: 配置試合 3 試合、ポイント算出（K/D・勝敗・生存時間の寄与）、降段条件、デケイ有無、シールド
- キュー: 対象モード一覧（MP）、BR での対象マッチ判定（対象外モード例: Warfare 等）
- リワード: ランク別報酬（カモ / BP / スキン / チャーム / コールカード）、Series（2 か月）の集結・リセット
- 成果物: `05_ranked.md`

### R3: Battle Royale
- マッチフロー: ロビー（solo/duo/squad）→ ロードアウト事前選択（武器数 / パーкъ / 装備）→ ガンシップ → ドロップ（降下・グライダー）→ ゾーン（フェーズ数 / 縮小タイミング / 域外ダメージ）→ 車両（一覧・挙動）→ ロードアウトドロップ（空投）→ 終了（順位 / キル / 報酬）
- BR 固有: ミニマップ、ゾーンタイマー、ルート・武器の配置、BR Ranked 統合ルール
- マップ一覧、100 名制の実仕様（スパーン / チーム構成 / ボット有無）
- **Web 実現性フラグ**: 100 名アソリュテイブシミュレーションの負荷 → スケーリング案（32 / 48 名化、ゾーン簡素化）とネットコード影響を R3 内で技術スパイクとして評価
- 成果物: `06_br.md`

### R4: Zombies（**別ミニ基準・後フェーズ**）
- 基準: 初出期には Zombies が存在しないため、本フェーズの基準（初出期）とは別に **2020-08 Zombies 導入バージョン**をミニ基準として参照する（`07` の冒頭で明記）
- 従来型: ウェーブ構造（雑魚種 / 出現スケール / インターミッション）、ポイント経済（キル毎）、ブイバック（コスト増分）、ミステリーボックス（コスト曲線 / 武器プール / 確率公開分）、パーкъの有無と効果、マップ構成、4 人制 / ソロプレイ時の挙動
- Undead Siege（2021 追加）は初出期・Zombies 導入直後とも離れるため**本研究では除外**（必要なら別途）
- 優先度: 決定2（MP+Ranked+BR 先行）により**後フェーズ**。研究自体は R4 として行うが、実装（Sフェーズ）は MP/Ranked/BR の後
- 成果物: `07_zombies.md`

### R5: プロgression と経済
- プレイヤー XP: レベル上限、XP 獲得テーブル（キル / オブジェクト / モード勝利 / double XP）、レベルアップ演出
- 武器 XP: 最大レベル、アタッチメントアンロック順（レベル別）、**カモシステム**（キル種別カウンター: 全キル / ヘッドキル / スティールキル / 無傷キル 等 → タイア閾値と色チェーン、武器毎 / 武器種毎の区別）
- ブループリント: 入手経路（BP / レベル / CP ショップ）、効果（外観 + 演出）
- キャラ: 一覧 / 入手方法 / キャラスキン
- メダルとチャーム: メダル一覧（獲得条件）、チャームの装着場所
- COD Points: 獲得（課金 / イベント）/ 消費先
- バトルパス: シーズン構造（2 か月）、フリー / プレミアム軌、レベル通貨、報酬種別一覧
- ショップ: 毎日リフレッシュ、バンドル構造、価格帯
- イベント: double XP 構造、チャレンジ型イベント、期間限定モードの投入方法
- 成果物: `08_progression_economy.md`

### R6: ソーシャル / 設定 / UI 総覧
- パーティ / スクワッド: 作成 / 招待 / 補完（MP のオートフィル有無 / BR の補完有無）、マッチ内チーム
- フレンド: 一覧 / 追加 / ステータス（マッチ中表示）、チャット（テキスト / クイックチャット / ボイスの有無）
- クランの有無を**検証**（存在しなければ明記）
- 設定: 映像 / 音声 / 操作（感度スライダー / レイアウト / 火器ボタンの位置）/ ハプティクス — **Web へのマッピング表**（実装可能 / 代替 / 不要）
- **UI スクリーン総覧**（デザイン再現の基盤。**決定3: 画面構成 1:1** — CoD Mobile 初出期のメニュー・画面構成・フローをそのまま踏襲し、視覚（カラー / 素材 / タイポグラフィ）のみ arsenal.io オリジナル）:
  - ハブ（トップバー: 通貨 / タブ構成）
  - Locker（武器 / キャラ / カモ / ブループリント / チャーム / 装備 のサブタブ）
  - Stats（全体 / モード別 / 武器別）、イベント、ショップ、ソーシャル、設定
  - マッチ関連: ロビー / カウントダウン / インターミッション / 終了画面
  - HUD 要素一覧（ヘルス表示の有無 / アモ / スコア / オブジェクトピップ / キルフィード / ミニマップ（BR））
  - **全画面の遷移図**（画面グラフ）+ 画面毎の要素リスト
- 成果物: `09_social_settings.md` / `10_ui_inventory.md`

### R7: 統合（最終成果物）
- 入力: R0–R6 全部
- 成果物: `docs/research/codm/INTEGRATION_SPEC.md`
  1. **最終機能マトリックス**: 各システム → 仕組みサマリ → Web 再現アプローチ → 優先度 P0–P3 → 粗効率
  2. **アーキテクチャ影響**: sim スケーリング（現 20 名 → N 名）、protocol 拡張、gameserver 変更、ネットコード（BR / zone）、マッチメイク + MMR、経済（実課金なしの mock 通貨設計）、**最終 IA / ルーティング**（旧デザイン案を置き換える確定版）
  3. **Sフェーズ計画**（実装順序: S0 スカフォールド → S1 MP コア → S2 Ranked/BR → S3 経済・ライブオプス …）
  4. **リスクと対応**
  5. **数値ポリシー**: 公開データがある値は正確再現、無い値は `[概算・設計値]` と明記して設計値を置く
- 完了基準: ユーザーレビュー → 承認 → Sフェーズ着手

## 3. ソースマップ

| 種別 | ソース | 用途 |
|---|---|---|
| 公式 | call-of-duty.com / CoD Mobile 公式ニュース・パッチノート | バージョン固定、公式ルール、イベント |
| Wiki | callofduty.fandom.com（Call of Duty Mobile Wiki） | モード / ランク / 武器数値 / 履歴の中心ハブ |
| コミュニティ | YouTube（モード解説 / ランクガイド）、Reddit r/CallOfDutyMobile、データマイニング記事 | 数値補完、実況観察、エッジケース |
| ゲーム内 | **ユーザー提供のスクリーンショット（決定4: 可）** | UI 総覧・数値の一次情報 |

- 全研究は `web_search` + `fetch_page` で実施。取得ページの内容は各ドキュメントにソース URL 付きで要約する（原文保存はしない）
- 数値がソース間で食い違う場合: 採用値 + 差異を明記し、信頼度を下げる
- **スクリーンショットの扱い**: ユーザーがプレイしているのは**現状版（2026）**。初出期 UI とは構成が異なる可能性があるため、スクリーンショットは「現在も同じ構造か」の確認用・共通コンポーネント（HUD / ロビー / マッチフロー）の参照に使う。初出期固有の画面は Web 上のリリース当初のレビュー / 動画（2019–2020）で補う。

## 4. リスク

| リスク | 対応 |
|---|---|
| 数値のパッチ追従ドリフト | 基準バージョンを R0 で固定。各ドキュメントに参照パッチ明記 |
| 100 名 BR の Web シミュレーション負荷 | R3 内での技術スパイク。32/48 名化・ゾーン簡素化の提案を含む |
| ライブオプス（イベント/BP）のスコープ肥大 | R7 マトリックスで P2/P3 化し S フェーズ後回し |
| 非公開データ（MMR 内部、確率等） | `[概算・設計値]` と明記し設計値を採用。推測と事実を分離 |
| DMZ の範囲爆発 | R0 で「研究対象にするかしないか」をまず決定（実装は P3） |
| CoD Mobile の地域/バージョン差（JP 版と海外版） | 基準バージョンに地域版も明記 |

## 5. 進め方（ルール）

1. 各 R フェーズ完了時: ドキュメント commit + 機能マトリックスの状態更新（`未着手 → リサーチ中 → 要クロス検証 → 確定`）
2. コード変更は**ゼロ**（Sフェーズ開始まで）。計画書と研究ドキュメントのみ
3. 各フェーズ開始前に、前フェーズの `[要クロス検証]` 項目をクリアする
4. R7 統合 Spec はユーザーレビューを必須ゲートにする
